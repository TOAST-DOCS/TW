## 핵심 검수 원칙 (Quick Reference)

### 필수 검수 항목

| 항목 | 검수 포인트 |
|------|------------|
| **어미** | 평서형: `-ㅂ니다` / 명령형: `-세요` / 의문형: `-겠습니까?` |
| **시제** | 현재형 원칙 (혼란 가능 시에만 과거/미래형) |
| **문장 길이** | 짧고 명확하게 (불필요한 보조동사 제거) |
| **번역 투** | `~을(를) 통해`, `~에 의해`, `~에 대한` 지양 |
| **외래어** | 국어 표현 우선, 외래어 표기법 준수 |
| **MMI** | 버튼명, 메뉴명 등은 **굵게** 표시 |
| **용어 통일** | NHN Cloud 용어 사전 참조 |

### 금지 표현

- 사동문: `~을(를) 시키다`
- 극존칭: `~하시겠습니까?`와 같은 이중 높임
- 구어체, 은어, 비형식적 표현
- 모호한 표현: `대부분`, `곧`, `간헐적으로`
- 이중 부정, 이중 피동
- 불필요한 조사 중복

## 독자 분석

### 원칙

1. **독자 정의**: 문서를 읽는 대상 독자가 누구인지 명확히 설정
2. **기술 수준 조절**: 독자의 배경 지식에 따라 기술적 깊이 조정
3. **사전 정보 제공**: 독자가 이해하는 데 필요한 정보를 미리 추가
4. **용어 풀이**: 전문용어가 처음 나올 때 반드시 설명 추가

### 검수 체크리스트

- [ ] 초급 개발자도 이해할 수 있는 수준으로 작성되었는가?
- [ ] 전문 용어에 대한 설명이 처음 등장 시 포함되었는가?
- [ ] 독자가 필요로 하는 사전 지식이 문서에 포함되었는가?

## 제목 작성 규칙

### 원칙

1. **요약성**: 제목은 아래 내용을 요약하여 전달
2. **설명 추가**: 제목 아래 1-2줄로 간단히 내용 요약
3. **구체성**: 사용자가 무엇을 할 수 있는지 구체적으로 명시
4. **제목 수준**: 장 제목 제외 3수준까지 권장
5. **단일 하위 항목 금지**: 하위 항목이 하나뿐이면 본문으로 통합
6. **마침표 생략**: 제목에는 마침표 사용 금지

### 좋은 예시 vs 나쁜 예시

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 푸시 | 푸시 알림 전송 방법 |
| 설정 | 사용자 권한 설정하기 |
| API | API 호출 가이드 |

### 검수 체크리스트

- [ ] 제목이 내용을 명확히 요약하는가?
- [ ] 제목 아래에 제목이 바로 연속되지 않는가?
- [ ] 제목에 마침표가 없는가?
- [ ] 하위 항목이 하나만 있지 않은가?

## 문장 작성 규칙

### 1. 문장의 주체와 동사

#### 원칙
- **사람이 주체**: 능동사 사용
- **서비스/제품이 주체**: 피동사 허용 (but 능동문 권장)
- **사동문 금지**: `~을(를) 시키다` 형태 사용 금지

#### 예시

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 체크 박스가 선택되어야 합니다. | 체크 박스를 선택합니다. |
| 설치 경로를 이동시킵니다. | 설치 경로를 이동합니다. |
| 생성되어집니다. | 생성합니다. |

### 2. 어미

#### 규칙

| 문장 형태 | 어미 | 예시 |
|----------|------|------|
| 평서형 | `-ㅂ니다` (격식 구어체) | 데이터를 저장합니다. |
| 명령형 | `-세요` (비격식 두루높임) | 파일을 확인하세요. |
| 의문형 | `-겠습니까?` (격식 구어체) | 파일을 삭제하시겠습니까? |

#### 극존칭 금지

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 확인하십시오. | 확인하세요. |
| 확인해 주세요. | 확인하세요. |
| 확인을 부탁드립니다. | 확인하세요. |

### 3. 시제

#### 원칙
- **현재형 원칙**: 모든 문장은 현재형으로 작성
- **예외**: 의미상 혼란이 생길 경우에만 과거형/미래형 사용

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| [닫기] 버튼을 클릭하면 대화 상자가 닫힐 것입니다. | [닫기] 버튼을 클릭하면 대화 상자가 닫힙니다. |

### 4. 형식적 표현

#### 금지 표현

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 서비스가 백그라운드에 띄워져 있는 경우 | 서비스가 백그라운드에서 동작하면 |
| 앱이 죽으면 | 앱이 종료되면 |
| 앱이 튕기는 현상 | 앱이 갑자기 종료되는 현상 |
| 에러를 잡아 | 오류를 수정해 |

### 5. 명확한 표현

#### 모호한 조건/시점 표현 금지

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| A 방법은 대개의 경우 효과적일 수 있습니다. | A 방법은 메모리 용량이 20% 이상 남아 있는 경우 효과적입니다. |
| A 작업은 곧 완료될 것입니다. | A 작업은 5분 이내에 완료됩니다. |
| 간헐적으로 발생할 수 있습니다. | 네트워크 연결이 불안정할 경우 발생합니다. |
| 대부분의 환경에서 작동합니다. | Windows 10 이상, 8GB RAM 이상 시스템에서 동작합니다. |

### 6. 짧고 쉬운 문장

#### 원칙
- 짧은 문장 우선 사용
- 불필요한 보조동사 제거: `-주다`, `-보다`
- 습관적 표현 제거: `처리하다`, `진행하다`

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 다음과 같이 구현해 주어야 합니다. | 다음과 같이 구현해야 합니다. |
| 추가를 합니다. | 추가합니다. |
| 결제를 진행한 사용자 | 결제한 사용자 |

### 7. 조사 중복 금지

| ❌ 권장하지 않음 | ✅ 권장 |
|----------------|--------|
| 기획에서부터 테스트까지 | 기획에서 테스트까지 |

#### 코드 텍스트(Inline Code) 사용 규칙

코드 텍스트(Inline Code)는 본문 내에서 코드, 메서드, 부호 등 코드 요소를 일반 텍스트와 시각적으로 구분하기 위해 사용하며, 강조 목적으로는 사용하지 않습니다.

##### 적용 대상

| # | 대상 | 설명 | 예시 |
|---|------|------|------|
| 1 | 설정값/속성명 | 시스템 설정 항목, 프로퍼티, 파라미터 이름 | `security.protocol`, `bootstrap.servers`, `auto.offset.reset` |
| 2 | 오류명/예외명 | 시스템이 반환하는 오류 코드, 예외 클래스 이름 | `InvalidTxnTimeoutException`, `NullPointerException`, `404 Not Found` |
| 3 | 메서드/함수 호출 | 괄호를 포함한 메서드, 함수 호출 | `commit()`, `abort()`, `flush()`, `subscribe()` |
| 4 | 파일명/경로 | 파일 이름, 디렉터리 경로 | `server.properties`, `/etc/kafka/`, `build.gradle` |
| 5 | 환경 변수 | 시스템 환경 변수 이름 | `JAVA_HOME`, `KAFKA_HEAP_OPTS` |
| 6 | 코드 값/상수 | 코드에서 사용하는 고정값, enum 값 | `true`, `false`, `null`, `read_committed`, `SASL_SSL` |
| 7 | Placeholder | API 경로, curl 예제 등에서 사용하는 대체 변수 | `{APP_KEY}`, `{tenantId}`, `${TOKEN}` |

##### 적용 예시

**본문 내 설정값 언급**

| 적용 전 | 적용 후 |
|---------|---------|
| security.protocol이 SASL_SSL로 설정되어 있는지 확인합니다. | `security.protocol`이 `SASL_SSL`로 설정되어 있는지 확인합니다. |
| transaction.timeout.ms 값이 300,000ms를 초과하지 않는지 확인합니다. | `transaction.timeout.ms` 값이 300,000ms를 초과하지 않는지 확인합니다. |

**본문 내 오류명 언급**

| 적용 전 | 적용 후 |
|---------|---------|
| 초과 시 InvalidTxnTimeoutException 오류가 발생합니다. | 초과 시 `InvalidTxnTimeoutException` 오류가 발생합니다. |

**본문 내 메서드명 언급**

| 적용 전 | 적용 후 |
|---------|---------|
| commitTransaction()을 호출하여 트랜잭션을 완료합니다. | `commitTransaction()`을 호출하여 트랜잭션을 완료합니다. |

> 참고: 괄호 없이 일반 동작으로 서술하는 경우("commit을 완료하지 않으면")에는 Inline Code를 적용하지 않습니다.

**본문 내 Placeholder 언급**

| 적용 전 | 적용 후 |
|---------|---------|
| {APP_KEY}는 콘솔에서 확인할 수 있습니다. | `{APP_KEY}`는 콘솔에서 확인할 수 있습니다. |
| URL의 {tenantId}를 실제 테넌트 ID로 대체합니다. | URL의 `{tenantId}`를 실제 테넌트 ID로 대체합니다. |

##### 미적용 대상

| # | 대상 | 이유 | 예시 (코드 텍스트 사용 금지) |
|---|------|------|---------------------------|
| 1 | 서비스/제품명 | 고유 명사이므로 일반 텍스트로 표기 | NHN Cloud, EasyQueue, Kafka |
| 2 | UI 요소 (MMI) | 기존 규칙에 따라 **볼드** 처리 | **확인**, **저장** |
| 3 | 명령어/연산 (괄호 미포함) | 일반 영단어와 겹치는 경우가 많아 맥락 판단 부담이 큼. 괄호 포함 메서드명은 적용 대상에 해당 | commit, abort, flush |
| 4 | 표(Table) 내 텍스트 | 표에 작성하는 것만으로도 일반 텍스트와 구분되어 가독성이 확보되므로 미적용 | security.protocol |
| 5 | 코드 블록 내부 | 코드 블록 전체가 이미 코드 서식이므로 중복 적용 불필요 | ``` 내부 코드 ``` |
| 6 | 강조 목적 | 단순 강조를 위해 코드 텍스트를 사용하지 않음 | [주의], 중요 |

##### 과적용 방지

**적용 판단 기준: 리터럴 테스트**

Inline Code 적용 여부가 애매할 때는 다음 질문으로 판단합니다.

> "독자가 이 텍스트를 코드나 설정 파일에 **그대로 입력**해야 하는가?"
> - **Yes** → Inline Code 적용
> - **No** → 일반 텍스트

| 텍스트 | 그대로 입력하는가? | Inline Code |
|--------|-------------------|-------------|
| security.protocol | O — 설정 파일에 정확히 입력해야 하는 속성명 | `security.protocol` |
| SASL_SSL | O — 설정값으로 정확히 입력해야 하는 값 | `SASL_SSL` |

## 용어와 약어

### 용어 작성 기준

| 기준 | 용례 |
|------|------|
| NHN Cloud 콘솔에서 서비스 이름, 왼쪽 메뉴와 헤더는 영어로, 메뉴를 클릭했을 때 오른쪽 영역에 나오는 본문, 탭 이름, 버튼 이름, UI 컨트롤 이름 등은 되도록 한글로 통일합니다. | |
| 전문 용어가 처음 나올 때는 용어 풀이도 함께 써 줍니다. | Cloud Monitoring 서비스의 용어 설명 |
| 한글로 바꿀 수 있는 용어는 한글로 적습니다. 한글만 썼을 때 바로 이해하기 어렵다면 뒤에 원문을 같이 적습니다. | 선형 검색(linear probing) |

### 조사

앞말이 한글이든 영어이든, 중간에 괄호가 삽입되든 상관없이 공백 없이 붙여 씁니다.

## 날짜, 버전, 단위

### 날짜

날짜는 연월일 순서로 씁니다.

#### 기본형
`2022년 3월 24일`

#### 요일 추가
요일은 괄호 안에 추가합니다.

`2022년 3월 24일(목)`

#### 축약형
년, 월, 일 글자를 생략하는 대신 마침표(.)를 사용할 수 있습니다.  
종종 마침표(.)를 생략할 때가 있는데, '일'을 생략하는 대신 마침표를 사용하는 것이므로, 마지막에도 마침표를 꼭 써야 합니다.  
띄어쓰기도 '년, 월, 일'이 있다고 생각하고 '년'과 '월'을 대신한 마침표 뒤에 한 칸씩 띄어 써야 합니다.

| 틀린 표기 | 옳은 표기 |

## 외래어 표기법

### 외래어에 대한 한글 표기 규정

원어가 영어인 용어를 표기할 때 다음 규정을 준수합니다.

#### 1. 원어의 발음을 기준으로 표기합니다.

원어의 표기(스펠링)가 아닌, 발음 기호를 확인합니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| directory[dɪrektəri] | 디렉토리 | 디렉터리 |
| locale[loʊˈkæl] | 로케일 | 로캘 |

#### 2. 받침에는 'ㄱ, ㄴ, ㄹ, ㅁ, ㅂ, ㅅ, ㅇ'만 사용합니다.

원어의 표기와 발음에서 해당 음절의 어말이 'p, t, d, k' 등이더라도 표기의 받침에는 'ㅍ, ㅌ, ㄷ, ㅋ'를 사용하지 않습니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| cake | 케잌 | 케이크 |
| platform | 플랱폼 | 플랫폼 |

#### 3. 된소리에 대해 쌍자음(ㄲ, ㄸ, ㅃ, ㅆ, ㅉ)은 사용하지 않습니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| server | 써버 | 서버 |
| thumbnail | 썸네일 | 섬네일 |

#### 4. 어말의 'sh'는 '시'로 적습니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| cash, cache | 캐쉬 | 캐시 |
| crash | 크래쉬 | 크래시 |
| push | 푸쉬 | 푸시 |

#### 5. 'ㅈ, ㅊ' 발음이 모음 앞에서 이중모음(ㅑ, ㅕ, ㅛ, ㅠ)이 되더라도 단모음(ㅏ, ㅓ, ㅗ, ㅜ)으로 적습니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| architecture | 아키텍쳐 | 아키텍처 |
| chart | 챠트 | 차트 |
| provision | 프로비젼 | 프로비전 |
| provisioning | 프로비져닝 | 프로비저닝 |
| region | 리젼 | 리전 |
| schedule | 스케쥴 | 스케줄 |
| version | 버젼 | 버전 |
| virtual | 버츄얼 | 버추얼 |

#### 6. 띄어 쓰기는 원어의 표기를 기준으로 합니다.

| 영문 | 틀린 표기 | 옳은 표기 |
|------|---------|---------|
| data lake | 데이터레이크 | 데이터 레이크 |
| website | 웹 사이트 | 웹사이트 |

### 예외 표현

외래어에 대한 한글 음차 표기는 기본적으로 외래어 표기법을 따르되, 일반적 또는 업계 내에서 이미 굳어진 표현은 관용을 따릅니다.

아래 표는 규범 표기에는 맞지 않지만 관용적으로 굳어진 표현의 목록입니다.  
목록은 지속적으로 업데이트하며, 알파벳 순으로 기재합니다.

| 영문 | 한글 표기 | 설명 |
|------|---------|------|
| credit | 크레딧 | 규범 표기는 '크레디트'이나, 관용에 따라 '크레딧'으로 적습니다. |
| lock | 락 | 규범 표기는 '로크'이나, 관용에 따라 '락'으로 적습니다. |
| solution | 솔루션 | 규범 표기는 '설루션'이나, 관용에 따라 '솔루션'으로 적습니다. |
| transit | 트랜짓 | 외래어 표기 규칙에 따르면 '트랜싯'과 '트랜짓'이 모두 맞는 표기이나 NHN Cloud 문서에서는 '트랜짓'으로 통일하여 적습니다. |
| window | 윈도우 | 규범 표기는 '윈도'이나, 관용에 따라 '윈도우'로 적습니다.<br>타사의 서비스명을 적을 때는 고유명사 표기 스타일 가이드에 따라 한글화하지 않고 원문을 정확하게 씁니다. |
